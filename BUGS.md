## 1. При открытии вкладки значения не отображаются
- Яркость/питание при открытии вкладки показывают `--`, хотя сервер значения, возможно, отдаёт
- После того как пользователь сам что-то поменял, значение отображается — но это то, что ввёл сам клиент, а не подтверждённое сервером
- Аналогичное поведение уже было со слайдером громкости
- **Дальше:** глянуть сырой JSON `GET /api/monitor/state` (devtools/curl): что реально приходит (null? число? задержка запроса?)

## 2. Power on/off показывается нестабильно
- Иногда верно (on=on, off=off), но чаще «от балды»
- Вероятно: DDC/CI-чтения flaky + читаем состояние сразу после переключения, пока монитор в переходе
- **Дальше:** ретраи чтения (2–3 попытки с паузой) в `MonitorService.GetValue`; задержка перед чтением после TurnOn/TurnOff
- ControlMyMonitor 1.43 имеет GUI-опцию «Try to read VCP code again if it fails in the first time» — подтверждает, что чтения падают

## 3. После выкл→вкл монитора яркость на клиенте сбрасывается на 0
- Сам монитор де-факто держит ту же яркость, а клиент после wake показывает 0
- Похоже, DDC-чтение сразу после wake возвращает 0/мусор
- **Дальше:** задержка + ретраи перед первым чтением после TurnOn; на клиенте не сбрасывать последнее известное значение

## Контекст
- ControlMyMonitor **v1.43** (NirSoft); команды: `/GetValue` (значение в exit code), `/SetValue`, `/TurnOn`, `/TurnOff`, `/SwitchOffOn`, `/stab`
- VCP: `10` = Brightness (0–100), `D6` = Power Mode (1=on, 4=standby, 5=suspend; у монитора possible values: 1,4,5)
- Код: `RemoteControl.server/Services/MonitorService.cs`, эндпоинты `/api/monitor/state|brightness|power`, UI — вкладка Monitor в `wwwroot/index.html`
